LINKAS - ARCHITECTURE
=====================

Linkas is a small video-call app (like Google Meet) with NO server: everything happens in the browsers of
the people in the call. After the meeting everyone gets the conversation and a summary.


1. THE BIG PICTURE
------------------

    Browser A  <====== video, sound, chat, recorded speech (WebRTC, direct, encrypted) ======>  Browser B
        \                                                                                       /
         \_____ only to find each other: public relays (Nostr), handshake encrypted by PIN ____/

    Static host (e.g. GitHub Pages): hands out the page files once. Takes no part in the call.

    The HOST's browser (whoever created the meeting) also keeps the meeting record:

        guests' browsers --- each piece of their own speech (direct) ---> host's browser
                                                                            | stores it (IndexedDB)
                            after the meeting                               v
                each person's speech -> WAV -> Gemini (speech -> text, with time stamps)
                                                                            |
                                         one conversation, ordered by time (+ chat, joins/leaves)
                                                                            |
                                                   Gemini (summary: topics, agreements, tasks)
                                                                            |
                                                                    the .txt transcript
                                            /                              |                        \
             sent directly to everyone      email to everyone (from      "Last meeting" card
             still in the call              the host's Gmail, Gmail API)  in the host's lobby

- Video and sound go directly between the browsers (every browser to every other one, max 8 people).
- The public relays only pass the encrypted handshake. They never see the call.
- No PC is a server. The host's browser only does what the host PC's server used to do after the meeting.


2. FILES
--------

  public/                The whole app: this folder is published as it is.
    index.html           The page: lobby, call screen, "meeting ended" screen.
    app.js               Everything in the call: joining, P2P connections (Trystero), media slots, buttons,
                         chat, background blur, mini window, voice recording; the host's side of joining
                         and storing speech; ending the meeting.
    meeting.js           The host's meeting record (IndexedDB) and the after-meeting steps: transcript,
                         conversation, summary, .txt text, emails.
    gemini.js            Google Gemini, called from the browser: speech-to-text (WAV) and the summary;
                         retries on rate limits, switches model when one is overloaded.
    gmail.js             Sends the emails from the host's Gmail (Google sign-in window + Gmail API).
    config.js            Settings of this copy: GOOGLE_CLIENT_ID (emails), TURN servers. Public, no secrets.
    util.js              Small helpers: time formats, file names, email check.
    style.css            The look (dark, green accent, fits phones).
    vendor/trystero.mjs  The P2P library, bundled into one file (npm run vendor).
    models/              Model for background blur (the blur engine itself loads from jsDelivr).
    logo.svg, favicon.svg, apple-touch-icon.png

  serve.js               Local test server (npm start -> http://localhost:3000). Not needed online.
  package.json           Only for the local test server and for rebuilding vendor/trystero.mjs.
  README.md              Full description.
  HOW-TO-START.txt       Step by step: publish the page, Gemini key, emails, a call.
  ARCHITECTURE.txt       This file.


3. SETTINGS
-----------

  Gemini API key         Typed by the host in the lobby; kept in that browser (localStorage), sent only
                         to Google. Needed for the transcript and summary.
  GOOGLE_CLIENT_ID       config.js. Lets the host's browser send emails from the host's Gmail.
                         Empty -> no emails; the transcript goes directly to everyone still in the call.
  TURN                   config.js. Only for networks that block direct connections.


4. A MEETING, STEP BY STEP
--------------------------

 1. CREATE    The host enters name, email, meeting name, a 4-digit PIN and the Gemini key.
              The browser makes a random code (abc-defg-hjk) and opens the meeting record (IndexedDB).
 2. INVITE    The host sends the link; the PIN is told separately.
 3. JOIN      A guest enters name, email and PIN. Their browser finds the meeting through the relays
              (code = room, PIN = encryption password; a wrong PIN cannot connect) and asks the host's
              browser to come in. The host's browser checks the meeting is on and not full, makes the
              name unique ("Tomas (2)") and answers with the meeting name and the chat so far.
 4. CONNECT   Every browser connects directly to every other one. Each connection gets one audio and
              one video slot; camera, mute and screen sharing only swap what goes through them.
              With more people, each copy of the video gets less bandwidth, so uploads keep up.
 5. TALK      While a microphone is on, that browser records only its own voice: it keeps the parts with
              speech and sends each piece (up to 20 s) to the host's browser with the moment it started.
              The host's browser confirms each stored piece; unconfirmed pieces are sent again when the
              host is reachable. Clocks are matched (every "hello" carries the sender's time).
 6. END       The host presses Leave -> "End meeting for everyone" (or leaves when alone).
              Every guest hands in its last piece and says so (or 8 s pass).
 7. WRITE     For each person: pieces are joined into recordings (max 5 min of speech each) -> WAV ->
              Gemini returns the text with time stamps -> each sentence is put back on its piece, so it
              gets the speaker's name and the real clock time.
 8. MERGE     All people + chat messages + joins/leaves are sorted by time.
 9. SUMMARY   Gemini writes: TEMOS, SUTARIMAI, VEIKSMŲ PUNKTAI.
10. SEND      The .txt goes directly to every browser still in the call ("Download summary"), and one
              email per participant goes out from the host's Gmail (.txt attached). The audio is deleted.
11. LATER     The host's lobby keeps a "Last meeting" card: download, "Try again", "Send again".


5. MESSAGES BETWEEN BROWSERS (Trystero actions)
-----------------------------------------------

  hello      to everyone      name, mic / camera / screen, "I am the host", "I am in the call", clock
  join       guest -> host    name + email; answer: final name, meeting name, chat, "emails are on"
  chat       to everyone      a chat message
  clip       guest -> host    one piece of speech (binary) + id + start time; answer: stored
  end        host -> all      the meeting is over
  flushed    guest -> host    my last piece is handed in
  progress   host -> all      how far the transcript is
  result     host -> all      the finished .txt (or the error)


6. WHEN SOMETHING FAILS
-----------------------

  Gemini overloaded or over its limit      -> retry, then the next Gemini model
  Gemini fails completely / no key         -> error shown to everyone; host's lobby card: "Try again"
                                              (the recordings stay in the host's browser until then)
  Summary fails                            -> the file has the conversation only
  Email fails or Gmail not allowed         -> lobby card: "Send again"; "Download summary" always works
  Someone's network drops                  -> reconnects by itself; speech recorded meanwhile is handed in
  Host's tab closes during the call        -> host opens the link again and joins: carries on as host
  Host's tab closes while processing       -> lobby card "Make it now" finishes it
  A network blocks direct connections      -> needs a TURN server in config.js


7. WHO SEES WHAT (PRIVACY)
--------------------------

  Other participants     your video, sound, chat
  Host's browser         chat, everyone's recorded speech (deleted after the transcript), the .txt
  Public relays          only the encrypted handshake (not the call)
  Static host            nothing from the call (it only serves the page files)
  Google (Gemini)        the recorded speech and the conversation text
                         (free tier: Google may use it to improve its products)
  Gmail                  the emails with the .txt (sent from the host's account)
